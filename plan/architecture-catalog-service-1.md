# Introduction

![Status: Planned](https://img.shields.io/badge/status-Planned-blue)

Implements the catalog-service design at `docs/2026-04-27-catalog-service-design.md` (rev 5, approved). Today's `mv:` cache evaporates on restart on installs without Redis → home feed cold every restart, recommendations and discover rows pay full plugin-dispatch cost. This plan migrates persistent media data to SQLite under a new `CatalogService` peer of `MediaService`. Cache role shrinks → live plugin calls only. Jobs precompute nightly. Read path = sub-ms DB hit + live fallback on miss.

7 phases = 7 PRs. Each ships independently; rollback = revert one PR. Each adds ≤ one job + ≤ one read site.

## 1. Requirements & Constraints

- **REQ-001**: New `CatalogService` peer of `MediaService`, lives `apps/server/src/catalog/`. Injected into `RowFetchContext`.
- **REQ-002**: 5 new tables: `canonical_metadata`, `discover_snapshots`, `recommendation_lists`, `user_history_mirror`, `user_ratings_mirror`. Drizzle schema, SQLite-first, Postgres-portable.
- **REQ-003**: `id_map` table (existing) ⊥ touched. Cross-provider IDs joined on `(tmdb_id, media_type)`.
- **REQ-004**: `preference_profiles.version` column (`integer NOT NULL DEFAULT 0`); `rebuild.ts` reads, increments, calls `profileStorage.write({ ..., version })`. `applyIncrementalUpdate` ⊥ touches it.
- **REQ-005**: 5 new jobs `host.catalog.*`, all `adminTriggerable: true`, all w/ explicit `runTimeoutSec`. Schedule: 02 / 04 / 06 / 07 daily + every-6h mirror sync.
- **REQ-006**: Catalog reads serve path = "DB hit OR live fallback to existing code." Catalog miss = ⊥ regression vs current behavior. ⊥ feature flag.
- **REQ-007**: Jobs sole catalog writer except bounded cold-fill on PE miss (write-back fire-and-forget, INSERT OR REPLACE idempotent).
- **REQ-008**: Per-user mutex + SQLite `BEGIN IMMEDIATE` on all mirror writes. Cursor merge inside tx via `max(prior, cursorTs)`.
- **REQ-009**: History + ratings live in separate tables w/ separate cursor blobs; ⊥ shared cursor.
- **REQ-010**: PE provider per-item `getItemFeatures(userId, tmdbId, type)` interface unchanged. New `CatalogPreferenceProvider` reads catalog, falls back to existing `MediaServicePreferenceProvider` on miss.
- **REQ-011**: `PreferenceEngine.rankCandidates` accepts `opts.deadlineMs` and threads to provider cold-fill; engine sites `engine.ts:149`, `rebuild.ts:200`, `incremental.ts:64` (incremental bypasses deadline).
- **REQ-012**: Watchlist ⊥ mirrored (V40). Always live MediaService dispatch.
- **REQ-013**: `recommendedForYou` cursor v2 = `{ p, pv }`; `pv` mismatch resets to `p=0`. Other catalog rows keep `{ p }`.
- **REQ-014**: `partial: true` propagates on hydrate miss (deadline-exceeded items dropped from emitted page).
- **REQ-015**: Eviction = nightly prune. Builds in-memory ref set (`recommendation_lists.items` + last-7d `discover_snapshots.items`) before DELETE pass. Skips when rec_build / `feature.preference.rebuild` running.
- **REQ-016**: `MediaService` gets 3 new methods: `getMetadata(tmdbId, type)` (system instance via global-scope `metadata@v1`), `getAllHistory(connId?)`, `getAllRatings(connId?)`.
- **REQ-017**: `JobService` gets `isRunning` re-export + `anyRunning(jobIds[])` helper.
- **CON-001**: SQLite-only v1. Postgres migration deferred. ⊥ multi-instance v1 (per-user mutex is process-local).
- **CON-002**: `@ent-mcp/shared` ⊥ touched unless new shared types added across server/client boundary.
- **CON-003**: All clean-code rules apply: single-responsibility, no hidden side effects, pure functions stay pure.
- **CON-004**: Code uses normal English (not caveman); design doc + commit messages may use caveman per skill.
- **CON-005**: V37–V45 in SPEC.md = invariants. Implementation must satisfy each.
- **GUD-001**: Use token-savior MCP (`get_function_source`, `get_edit_context`) for targeted reads where possible.
- **GUD-002**: Each PR ships a changeset per CLAUDE.md (1–2 sentences, end-user voice, past tense).
- **GUD-003**: Run `vp check` + `vp test` before every commit (memory guardrail #9).
- **GUD-004**: Every reported bug gets a regression test (memory guardrail #12).
- **PAT-001**: Job registrations live next to consumers (per job-service spec). Catalog jobs in `apps/server/src/catalog/jobs/*.ts`, registered at server bootstrap.
- **PAT-002**: Drizzle table definitions one-per-domain in `apps/server/src/db/schema/catalog.ts` (single file v1; split if >300 lines).

## 3. Alternatives

- **ALT-001**: Read-through MediaService (Approach 2 in design). Make MediaService methods consult DB first, dispatch to plugin on miss. Rejected: blurs MediaService responsibility, makes invalidation hard to reason about, test surface explodes branching on DB-vs-plugin per method.
- **ALT-002**: Pure CQRS materialized views (Approach 3). Each home row = its own table. Rejected: heavy schema churn per row, duplicates canonical metadata across N tables, doesn't fit live-data needs (watchlist).
- **ALT-003**: Denormalize cross-provider IDs onto `canonical_metadata`. Rejected: drift between `id_map` and metadata, two writers, no win on hot path (IDs only needed by jobs).
- **ALT-004**: Mirror watchlist locally. Rejected: watchlist volatile, source of truth always plugin; live dispatch acceptable cost for low-frequency operation.
- **ALT-005**: Plugin-side `since` cursor for incremental sync. Rejected: plugin contract uneven (Trakt has it, Plex/Jellyfin don't); host-side diff against mirror works for all plugins uniformly.
- **ALT-006**: Row-per-event mirror tables (vs blob). Rejected for v1: blob simpler for users < 10K events. Migration path documented if scale demands.
- **ALT-007**: In-process LRU above CatalogService DB reads. Rejected: SQLite indexed PK lookup already sub-ms; cache adds invalidation surface w/ no measurable win.

## 7. Risks & Assumptions

- **RISK-001**: `enrichCandidates` cold-fill burst on a fully-cold catalog could storm TMDB. Mitigated by CONCURRENCY=10 cap (TASK-019) + deadline (TASK-020). First-install user should still expect slower first home load.
- **RISK-002**: Per-user mutex is process-local. Multi-instance future requires Postgres advisory locks (deferred per design Open Questions). Documented.
- **RISK-003**: `getAllHistory` for power Trakt user (10K events) full-fetch cost every 6h. Plugin contract change to `since`-aware fetch is v2 work (deferred).
- **RISK-004**: SQLite single-writer means 5 nightly jobs serialize writes. Schedule staggering (02/04/06/07) avoids overlap by construction; runtime-bound math holds (90+60+30+30 = 210 min < 18h between 02:00 and next day's 02:00).
- **RISK-005**: Mirror blob unbounded; 100K events ≈ 5MB blob, expensive to re-write per sync. Tracked via Open Question; migration path = blob → row-per-event table.
- **RISK-006**: Profile-version mid-scroll reset is silent UX (user on p=2 jumps to top). UX surface (toast) deferred per design Open Questions.
- **RISK-007**: `INSERT OR REPLACE` for canonical_metadata `created_at` requires care to preserve original timestamp on update. Implementation must use `COALESCE(existing.created_at, now)` pattern (TASK-012).
- **RISK-008**: `recordAccess` map lost on restart → first-read-after-restart UPDATE storm for warm keys. Bounded (one UPDATE per warm key per restart); amortized within an hour. Acceptable.
- **ASSUMPTION-001**: `metadata@v1` is global-scope (no per-user binding). Verified via plugin SDK manifests (TMDB plugin uses admin-pool credentials).
- **ASSUMPTION-002**: `recommendations@v1` plugins (Trakt) return items w/ `tmdbId` in resolvable form (compatible w/ `id_map`). Verified by today's row fetcher behavior.
- **ASSUMPTION-003**: Existing test helpers in `apps/server/src/__tests__/helpers/` provide a way to construct `RowFetchContext` for tests; extend rather than replace.
- **ASSUMPTION-004**: `host.preference.daily_rebuild` (existing) keeps running alongside `host.catalog.recommendation_build` until Phase 4 fully replaces its rec-list-writing role. Phase 4 either subsumes the existing job or runs them sequentially in the same handler.
- **ASSUMPTION-005**: `feature.preference.rebuild` registration location is findable via repo search (TASK-045). If not found, file added in Phase 4 alongside the catalog job.

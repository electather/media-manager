# Introduction

![Status: Planned](https://img.shields.io/badge/status-Planned-blue)

Implement diagnostics service per `docs/2026-05-08-diagnostics-design.md`. Two outcomes one PR-stack:

1. **Rename** all `errors` modules → `diagnostics` (server, shared, client). API + DB-table schema renames where harmless. `error_records` table NAME unchanged (deliberate).
2. **Add perf**: new `perf_records` table, `capturePerf` API, HTTP middleware, plugin runtime instrumentation, admin Perf tab w/ p50/p95/p99 aggregation.

Spec: `docs/2026-05-08-diagnostics-design.md`
Stack: Hono mw, Drizzle/SQLite, React 19 + TanStack Router/Query.

Pre-stable per `CLAUDE.md` → API + DB breaking changes acceptable. ⊥ shim, ⊥ deprecation.

## 1. Requirements & Constraints

- **REQ-001**: ∀ HTTP RPC handler matched by hono router → 1 perf row.
- **REQ-002**: ∀ plugin sandbox invoke (success ∨ failure) → 1 perf row w/ duration.
- **REQ-003**: ∀ err record ∧ ∀ perf row tagged same `requestId` (UUID) sourced from AsyncLocalStorage.
- **REQ-004**: HTTP perf `route` = hono `c.req.routePath` (param pattern). ⊥ raw URL.
- **REQ-005**: HTTP perf skips: `!c.req.routePath`, `route.startsWith("/api/diagnostics")`, streaming/SSE responses.
- **REQ-006**: `error_records` table NAME unchanged. Drizzle table identifier may rename; SQL name preserved via `pgTable("error_records", ...)` style binding.
- **REQ-007**: `app_config` extended w/ `perf_retention_days` int default 7. Existing `error_retention_days` unchanged.
- **REQ-008**: `DiagnosticSink` interface — both `captureError?` ∧ `capturePerf?` optional. Sink missing matching method = silently skipped.
- **REQ-009**: Built-in sinks: `DatabaseSink` (both), `NotificationErrorSink` (errors only). ⊥ external sinks v1.
- **REQ-010**: Admin Perf tab aggregates last-N-window via JS-side calc; bounded read max 50 000 rows. Beyond → SQL `LIMIT/OFFSET` per group fallback.
- **REQ-011**: API rename `/admin/errors/*` → `/admin/diagnostics/*`. New: `/admin/diagnostics/perf/{aggregate,list,:id,summary}`. FE call sites updated same PR.
- **REQ-012**: FE `reportError` POSTs to `/api/diagnostics/errors`. Body includes `requestId`. Header `X-Request-Id` also set.
- **REQ-013**: Admin route file `apps/client/src/routes/_authenticated/_settings/admin/logs.tsx` → `admin/diagnostics.tsx`. Tabs: Errors | Performance.
- **REQ-014**: Cron job rename `host.errors.retention_sweep` → `host.diagnostics.retention_sweep`. Sweeps both tables independently.
- **REQ-015**: Permissions unchanged — `admin:plugins` gates all `/admin/diagnostics/*`.
- **REQ-016**: Changeset 1-2 non-technical sentences (memory rule #11). Bump = minor for `@ent-mcp/server` ∧ `@ent-mcp/client` ∧ `@ent-mcp/shared` not listed (internal).
- **CON-001**: ⊥ new top-level deps. Reuse Date.now() for timing, no `perf_hooks` import unless already pulled.
- **CON-002**: ⊥ flat files >300 LOC. Decompose per memory rule #17.
- **CON-003**: `vp check && vp test` green per commit (memory rules #8 #9).
- **CON-004**: Capture errors in sinks ⊥ break app. ∀ writes `Promise.allSettled`; failures swallowed.
- **CON-005**: Shared package zero runtime deps beyond zod (catalog).
- **GUD-001**: Shared symbols imported direct from `@ent-mcp/shared/diagnostics` — no local re-export shim.
- **GUD-002**: Enums = `as const` tuples (`ERROR_SEVERITIES`, `ERROR_SOURCES`, `PERF_KINDS`).
- **GUD-003**: Reuse existing `NotificationErrorSink` filter logic; only adapt to new iface.
- **PAT-001**: Single-module layout per Approach A: `apps/server/src/diagnostics/` flat, `capture.ts` holds both `captureError` + `capturePerf`.
- **PAT-002**: One file per surface in admin viewer. Perf tab decomposed: `perf-tab.tsx`, `perf-table.tsx`, `perf-drill-sheet.tsx`, `perf-stats-cards.tsx`.
- **PAT-003**: Hono RPC types end-to-end. ⊥ hand-typed DTO. Client reads from `AppType`.

## 3. Alternatives

- **ALT-001**: Single `log_records` table w/ `kind` discriminator. Rejected — schemas diverge (perf has duration/route, errors have stack/severity/code), nullable col bloat, coupled retention.
- **ALT-002**: Two parallel modules (`errors/` + `perf/`) under `diagnostics/` umbrella. Rejected — premature dir tax; both serve admin viewer same way; flat `diagnostics/` simpler.
- **ALT-003**: Ship via OpenTelemetry SDK + Sentry/GlitchTip backend. Rejected — self-host ethos (existing doc §V3), bundle weight, ops burden, sampling losses. Sink iface keeps door open as adapter v2.
- **ALT-004**: Pre-aggregated rollup tables (hourly/daily). Rejected v1 — on-the-fly query at self-host scale = fine. Revisit v2 if window queries slow.
- **ALT-005**: Capture DB query timing v1 via Drizzle wrapper. Rejected — high volume drowns signal; HTTP timing surfaces slow routes first.

## 7. Risks & Assumptions

- **RISK-001**: Hono `c.req.routePath` may differ across versions. Verify exact API at TASK-021. If absent, use `c.req.matchedRoute()?.path` or matched-route walker.
- **RISK-002**: Capture-all w/o sampling at high traffic → DB bloat. Mitigation: 7d default retention + clamp 1-90d. Open Q sampling v2.
- **RISK-003**: SQLite `percentile_cont` ⊥ supported. Mitigation: JS-side calc bounded 50k rows + per-group LIMIT/OFFSET fallback.
- **RISK-004**: Plugin runtime invoke wrap may already swallow throws — confirm `capturePerf` runs in `finally` regardless.
- **RISK-005**: Cron migration: old `host.errors.retention_sweep` row in jobs table. Mitigation: pre-stable, manually delete or add one-off cleanup; or scheduler reconciles by-id on boot.
- **RISK-006**: TanStack Router auto-route-tree regen needed after file rename. If route tree is committed (not gitignored), regen + commit.
- **ASSUMPTION-001**: `apps/server/src/db/schema/errors.ts` is the canonical schema location and migrations are generated via Drizzle Kit.
- **ASSUMPTION-002**: `app_config` is a single-row table accessed via getter/setter helpers.
- **ASSUMPTION-003**: `cuid2` id generator already in use for `error_records.id` and `perf_records.id` adopts same.
- **ASSUMPTION-004**: i18n via Paraglide present and admin keys under `apps/client/messages/admin/`. If absent, inline strings v1 + open Q.
- **ASSUMPTION-005**: Bootstrap registers sinks at server startup once. ⊥ per-request registration.
- **ASSUMPTION-006**: No external sink consumers to migrate (interface change is internal-only).
